# 모의 면접 진행

[공통 규칙](references/workflow.md)과 [면접 규칙](references/interview-workflow.md)을 적용한다.
사용자의 명시적 요청이 기본 모드·문항 수·진행 방식보다 우선한다.

## 시작

선택한 자료와 목표 직무로 시작한다. 준비 자료가 없으면 목표 직무와 다룰 경험 하나만
물어 일반 연습을 한다. 프로젝트·구조화 파일·handoff·앱 설치는 선행 조건이 아니다.
이미 정한 목표와 자료 선택을 반복 확인하지 않는다.
코칭은 답변마다 피드백, 실전 연습은 종료 후 피드백이다. 기본은 코칭·핵심 질문 3개다.
현재 접근 가능한 자료만 사용하고 자료별 버전 또는 선택한 발췌를 고정한다.
이전 session JSON으로 재개하면 검사 후 마지막 미완료 질문·답변 revision부터 이어간다.
검사 도구가 없으면 미검증으로 표시하고 사용자와 읽기용 요약을 확인해 계속한다.

## 한 질문씩 진행

1. 질문 하나만 제시하고 답변을 기다린다. 근거가 있는 질문은 선택 자료의 참조를 남긴다.
   공백 질문은 없는 경험을 전제하지 않고 여부를 묻는다. 답변·질문을 대신 지어 완료하지 않는다.
2. 텍스트 입력은 사용자가 보낸 답변으로 취급한다. 음성은 실제 보이는 전사만 사용하고,
   특히 기간·수치·고유명사·부정·본인/동료 기여를 짧게 확인해 사용자가 수정·확인하게 한다.
   전사가 보이지 않으면 확인 가능한 답변 텍스트를 요청한다. 확인 전에는 평가하지 않는다.
3. 확인한 답변만 평가한다. JD 대응, 행동·근거, 직접/공동 기여, 기간·수치 일관성,
   설명 명료성에서 제공된 내용으로 판단 가능한 부분을 설명한다. 발음·침묵·말투·전사 품질로
   역량을 추정하거나 합격 확률·채용 순위를 제시하지 않는다.
4. 코칭에서는 좋은 점 하나, 보완점 하나, 필요한 꼬리 질문 하나를 제시한다.
   실전 연습에서는 도중 평가를 생략하고 필요한 확인 질문만 한다.
   새 답변으로 확정되지 않은 AI 답변 예시는 `예시/빈칸`으로 표시한다.
5. 답변을 수정하면 revision을 올린다. 이전 revision의 평가·후보는 stale로 남기고
   현재 답변의 사실로 재사용하지 않는다. 재평가는 확인한 최신 답변만 대상으로 한다.

## 중단·복습·저장

사용자가 쉬기/중단/끝내기를 요청하면 즉시 질문을 멈춘다. 완료하지 않은 문항은 미완료다.
종료 시 `interview-reflect`로 연결하고 질문/확인한 답변/AI 피드백/새 사실 후보를 구분한다.
새 후보는 pending이며 사실 확인·사용 허용은 `career-review`에서 별도 검토한다.

저장을 요청하면 [세션 schema](references/schemas/interview-session-1.0.schema.json)에 따라
선택 발췌·제약·질문·답변 revision·확인 상태·피드백·pending·다음 단계를 기록한다.
[interview.py](references/interview.py)로 검사하고 같은 버전 Markdown을 생성한다.
파일 도구가 없으면 복사 가능한 요약과 미저장 상태를 제공한다. JSON을 핵심 사용의 조건으로
요구하지 않는다. 자동 저장·완전한 기억·파일 다운로드 완료를 추정하지 않는다.
